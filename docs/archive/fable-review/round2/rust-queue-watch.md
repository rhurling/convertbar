### 1. `preset_cache` mutex held across HandBrake shell-out (was High, verified Medium) — B2
**Verdict: FIXED.**

The helper (src-tauri/src/commands/handbrake.rs:38-58) scopes the guard: check-hit block at :43-48 drops the lock, `hb::get_preset_metadata` shell-out at :50 runs unlocked, re-lock + insert at :52-56, with a comment documenting the accepted duplicate-fetch race. ### 3. `scan_folder` / `classify_paths` sync commands doing unbounded recursive walks (Medium) — B2
**Verdict: FIXED.**

### 4. Watched path stored verbatim, UNIQUE only byte-identical (Medium) — B5
**Verdict: FIXED** (with one residual gap, see New findings: pre-existing rows are not migrated).
Evidence: `canonical_watch_path` (src-tauri/src/commands/watch.rs:41-45) applies `dunce::canonicalize` (avoids Windows `\\?\` prefixes) and is called first thing in `add_watched_directory` (watch.rs:55), before the `is_dir` check and the INSERT, so the UNIQUE constraint now compares canonical forms. Non-existent paths pass through unchanged so `is_dir()` still owns the clear rejection (watch.rs:227-234 test). Tests cover trailing-separator//./ aliases (watch.rs:194-208) and unix symlinks (watch.rs:210-224). `dunce` is a proper dependency (Cargo.toml).

### 5. `reconcile` never purges `pending` under removed/disabled watches (Medium) — B5
**Verdict: FIXED.**
Evidence: `removed_watch_roots` (src-tauri/src/watcher.rs:85-94) computes truly-going-away roots while excluding the mode-flip case (path present in both `to_unwatch` and `to_watch`) — exactly the caveat flagged in round 1; `purge_pending_under` (watcher.rs:99-107) drops pending entries under those roots; `reconcile` calls both at watcher.rs:505-508. Ordering is race-free: `configs` is replaced with the desired set at watcher.rs:494-496 *before* the purge, and the event handler holds the `configs` guard across its `pending.insert` (watcher.rs:246-275), so no event using stale configs can insert after the purge runs. Tests: mode-flip exclusion (watcher.rs:720-729) and purge-only-under-removed-roots with separator-safe `Path::join` fixtures (watcher.rs:732-754).

## New findings

Reviewed diffs: `git diff eb44d4b..HEAD` over queue.rs, watcher.rs, watch.rs, db.rs, plus the new/changed helpers they reference (commands/handbrake.rs `cached_preset_metadata`, commands/settings.rs `read_suffix_template`). Adversarial checks performed: lock-ordering re-derivation for the new purge call (reconcile: configs → watched → pending → watcher; event handler: configs→pending; no cycle — and the configs swap at watcher.rs:494-496 happens *before* the purge while the event handler holds `configs` across its `pending.insert`, so no stale-config insert can land after the purge), Windows separator audit of every new test (all use `Path::join`/`MAIN_SEPARATOR`/same-PathBuf round-trips — separator-safe), and an empirical macOS check that `fs::canonicalize` resolves case variants to on-disk case (it does: `casetest` → `CaseTest`), so the `canonical_watch_path` doc claim holds. Full suite: 127 passed, 0 failed, 2 ignored (the e2e pair, enforced by the scheduled job per D6).

- **[Low]** src-tauri/src/commands/watch.rs:55 / src-tauri/src/db.rs — **pre-fix watched_directories rows are never canonicalized (no backfill migration)**. `canonical_watch_path` runs only on new inserts; rows written before this fix keep their verbatim path. Failure scenario: a user who watched `/tmp/incoming` pre-fix re-adds the same folder post-update — dunce yields `/private/tmp/incoming`, the UNIQUE check compares canonical-new vs verbatim-old, passes, and two watchers over one folder result (exactly the duplicate the fix targets). A one-time `UPDATE watched_directories SET path = canonical(path)` pass in init-time Rust (with UNIQUE-collision handling) would close it. Realism is modest — the picker usually emits resolved paths — hence Low.
- **[Low]** src-tauri/src/watcher.rs:99-107, 505-508 — **`purge_pending_under` overreaches with nested watches**. Removal of an enclosing root purges pending entries that belong to a still-active nested watch: with `/w` (recursive) and `/w/sub` both watched, a file mid-stabilization under `/w/sub` `starts_with(/w)` and is purged when the user removes only the `/w` watch. If the file's writes had already finished (it was merely waiting out its stability delay, so no further FS events arrive), it is silently never enqueued despite its own watch staying active — until a restart/re-enable rescan. Fix shape: retain entries that still match any *desired* config (`delay_for_path(&desired, path).is_some()`) instead of testing only removed roots. Nested watches are an unusual config (round 1 rated the whole overlap class Low), so Low.
- **[Low]** src-tauri/src/commands/watch.rs:93,153; src-tauri/src/watcher.rs:260,464-467 — **in-flight background scans are not cancelled by watch removal/disable** (fresh pass; pre-existing, but adjacent to the B5 fix and now the only remaining path by which a removed watch keeps converting). `scan_existing_background` spawns a detached thread that scans + probes (potentially minutes for a big folder with skip-by-source-media on) and then enqueues via `enqueue_and_start`, bypassing `pending` entirely — so the new purge cannot stop it. Scenario: user adds the wrong (huge) folder, immediately removes the watch; every video in it is still probed and enqueued. Fix shape: re-check membership against current configs at the `enqueue_and_start` chokepoint, or have scan threads check a generation counter bumped by `reconcile`.
- **[Low]** src-tauri/src/db.rs:93-100 — **the preset repair matches by name only, on every platform**. `UPDATE settings SET value = 'H.265 MKV 1080p30' WHERE ... value = 'H.265 MKV 1080p'` also fires for a *user-created custom preset* that happens to carry the old name — the most plausible owner being a Linux user who worked around the original bug by defining a custom preset named exactly "H.265 MKV 1080p" in their presets.json. Their deliberate choice is silently switched to the built-in 1080p30. Self-limiting (the built-in exists, conversions work) and the window is tiny; note-level Low. No action needed unless a support report surfaces.

No new Critical/High/Medium issues found in the fix diffs. Specifically checked and clean: the `cached_preset_metadata` unlock-fetch-relock (documented duplicate-fetch race is benign; error path leaves the cache untouched and unpoisoned, tested at handbrake.rs:206-214), the `read_suffix_template` default-vs-explicit-empty semantics (B8; preserves a deliberate in-place choice, tests at settings.rs:190-220), the sync→async command signature changes (transparent to `invoke()`, app commands ACL-exempt), and the reaper/reconcile interleaving (a file harvested by the reaper in the same tick the user disables its watch is enqueued — inherent 1s-granularity race with user action, not a code defect).

## Summary

All five round-1 High/Medium findings in the queue/watch area are genuinely fixed in current main (daf4f8e), verified in source rather than from TRIAGE checkboxes: the preset-cache lock convoy is gone via a shared scoped-lock helper (plus the four handbrake.rs sync commands moved off the main thread), the Linux default preset is corrected *and* retroactively repaired for already-seeded DBs with tests on both the repair and its non-interference with user choices, both remaining sync recursive-walk commands are on `spawn_blocking`, watch paths are dunce-canonicalized before the UNIQUE check with symlink/trailing-separator tests, and `reconcile` purges pending entries under removed roots with the mode-flip case explicitly excluded and race-freedom guaranteed by the configs-swap-before-purge ordering. B11's extractions (`reap_pending_once`, migration test, `parse_preset_list`, `take_pause_after_current`/`final_run_status`) landed with intent-encoding tests; the old-schema migration test covers the previously untested ALTER path. No Windows-only hazards found in any new test (all separator-safe). The four new findings are all Low: two residual edges of the B5 fixes (no canonicalization backfill for old rows; nested-watch purge overreach), one adjacent pre-existing lifecycle gap (uncancellable in-flight scans), and one cosmetic over-broad match in the preset repair.
