# An unreachable host books an error and pauses the queue

When a remote job cannot reach its ssh host (ssh's own exit status 255), the job is booked as an error with the failure class `unreachable` and its post-convert hook fires once, as for any finished job. The queue then takes a persisted pause and remembers which job hit the outage, so a restart does not retry into it. The next queue start re-queues that one job and lifts the pause, and the re-queued job starts again from the pull. `/api/status` keeps its existing values and reads `stopped` (work queued, queue not running), so the dashboard's contract is unchanged. The low-disk stop instead leaves its job queued and fires no hook, but the hook receivers need to learn about the outage from the job that hit it. Rejected: leaving the job queued and firing post-convert anyway, which breaks "one post-convert per finished job"; a third hook event for pauses, which every receiver would have to learn; an unpersisted stop, which every restart during an outage would turn into one more failed job; and re-queueing every `unreachable` row on each start, which would resurrect rows from long-past outages.
