# An unreachable host books an error and pauses the queue

When a remote job cannot reach its ssh host (ssh's own exit status 255), the job is booked as an error with the failure class `unreachable` and its post-convert hook fires once, as for any finished job. The queue then takes a persisted pause, so a restart does not retry into the outage, and `/api/status` reads `paused` with no new state value. Start, Resume, or an add lifts the pause and re-queues the `unreachable` rows. A re-queued job starts again from the pull. The low-disk stop instead leaves its job queued and fires no hook, but the hook receivers need to learn about the outage from the job that hit it. Rejected: leaving the job queued and firing post-convert anyway, which breaks "one post-convert per finished job"; a third hook event for pauses, which every receiver would have to learn; and an unpersisted stop, which every restart during an outage would turn into one more failed job.
