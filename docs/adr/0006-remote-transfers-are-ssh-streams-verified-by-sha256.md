# Remote transfers are ssh streams verified by SHA-256

A remote job moves files by running the system `ssh` with the account's config (host aliases, `BatchMode=yes`), streaming the source down with `cat` and the result up into a marked temp file. It then compares the pushed file's size and remote `sha256sum` against the local copy before anything is replaced. rsync was rejected for this cycle. macOS ships openrsync while Homebrew ships GNU rsync, so behaviour would depend on PATH. Its integrity check is also implicit, where the contract wants an explicit verification before an original is deleted. The cost: a transfer interrupted over a slow link restarts from zero, which may matter once the VPS's media is remote. A Rust ssh library was rejected because it would not read the account's ssh config. Remote hosts must offer a POSIX shell and GNU coreutils (`stat -c`, `realpath`, `sha256sum`, `chown --reference`).
