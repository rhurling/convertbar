# A remote job runs the local pipeline on a staging copy

Every safety gate in the queue thread assumes `source_path` is a local file: the vanished-source check, the low-disk gate, the readability check behind failure classification, the condemned-identity stamp, crash recovery's partial cleanup, and purge. A remote job therefore pulls its source into a local staging directory and runs that unchanged pipeline on the copy. The remote part only wraps it: pull before, and verify, chown and replace-or-delete after, in place of the local cleanup arms. A job records its host in a nullable `remote_host` column beside the remote absolute paths, and the API names the host in a separate `remote` field. The rejected alternative was teaching each local seam about remote paths, where one missed seam deletes or stats the wrong file. An `unraid:/path` string in `source_path` was rejected too, because `Path::new` reads it as a relative local path, and a macOS path may legally contain a colon. Purge refuses remote rows: it would otherwise delete a local path.
