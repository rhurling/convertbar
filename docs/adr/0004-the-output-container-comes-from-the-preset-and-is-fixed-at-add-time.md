# The output container comes from the preset and is fixed at add time

ConvertBar used to name every output `.mp4`, and HandBrakeCLI picks the container from the output's extension, so an MKV preset silently wrote MP4 and lost the tracks MP4 cannot carry (ASS/PGS subtitles, DTS/TrueHD audio). The extension now comes from the preset's `FileFormat` (`av_mp4`, `av_mkv`, `av_webm`; a missing field means MP4, an unknown value refuses the add). It is decided when a job is added and stored in its `output_path`, just as the preset name is. The in-place check follows that extension. The cost: every add needs the preset's metadata, so an add now requires HandBrake even with a literal suffix. Rejected: falling back to `.mp4` when HandBrake is absent, which recreates the mismatch; and passing `--format` at encode time, which would leave the stored name and the container free to disagree.
